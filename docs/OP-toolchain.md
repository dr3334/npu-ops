# OP-toolchain —— MTK NeuroPilot SDK 工具链清单与可运行示例

> 范围：`neuropilot-sdk-basic-7.0.8-build20240807/neuron_sdk`（host 侧，WSL 内 x86-64 可执行）。
> 目的：把「参考编译器」当黑盒研究之前，先把**有哪些工具、哪些开关、怎么跑**钉死。
> 日期：2026-11-14 · `ncc-tflite` 版本 **7.3.15**

## 0. 一句话

这套 SDK 只有 **6 个**可执行文件；先前设想的 **NeuronBuild / NCC Tile 不存在**。
其中 4 个（`ncc-tflite` / `readdlb` / `dla-packer` / `mdla-bwhint`）已经提供了足够的**结构视图**，
不需要一上来就逆向二进制。

## 1. 工具清单

`neuron_sdk/host/bin/`（与 `mt6897/bin/` 同名同集；host 版是 x86-64，芯片版是 aarch64）：

| 工具 | 作用 | 关键开关 |
|---|---|---|
| `ncc-tflite` | 把 `.tflite` 编译成 `.dla`（可执行推理 `-e`） | 见 §2 |
| `neuronrt` | 在设备上执行 `.dla` | `-m hw` / `-a` / `-i`（可多个，按顺序）/ `-o` / `-c` / **`-d`（打印 I/O id-shape-size 表）** |
| `dla-packer` | 把若干 `.dla` 打成 `.dlb` | `-o` / `--share-tmp-buf` / `--ext-static-data` / `-l 0..9` |
| `readdlb` | 读 `.dlb`，打印结构信息 | `--share-tmp-buf-alignment` |
| `extract-shared` | 抽取共享权重（ADR 0006 那条路） | 无 `--help`（`Option 'help' does not exist`） |
| `mdla-bwhint` | 给 `.dla` 编码/解码**带宽提示（JSON）** | `-d`（dump）、`-o`、`-v`（hint 格式版本，缺省 2）。位置参数永远是 `hint dla`：**`-d` 时第一个是输出**。**已跑通**，见 §4 |

## 2. `ncc-tflite` 的开关（按用途分组，全部来自 `--help`）

### 2.1 三个「结构视图」开关到底给了什么（[`06`](../reports/compiler-blackbox-06.md) 实测）

| 开关 | 写进产物 | 可读性 |
|---|---|---|
| `--show-exec-plan` | 0（只印日志） | 层序 / target；**产物里没有层名**（普通产物搜不到 `FULLY_CONNECTED`） |
| `--show-memory-summary` | 0 | `Input/Output/Temp/Static/Code/Total` 六列；`=1/2/3/4` 四种 mode **输出逐字节相同**；`Static` = 常量块字节和、`Total` = 五列之和（一位小数 KiB 口径） |
| `--show-l1-req` | **0**（+14 B 全是命令行回显） | help 原文：*Only effective when global buffer allocation is in effect* —— 单算子图没有，所以 `L1: 0` |
| `--gen-debug-info` | **+539 B** | 结构化记录、含 ASCII `FULLY_CONNECTED`；**无官方 host 读取器**（`readdlb` 看不到、`neuronrt -d` 只印 I/O）；**且它不是运行时 profiling 认的段**——认的是 `-P<n>`（[`07`](../reports/compiler-blackbox-07.md) §7.1） |
| `--gen-urate-info` | **+269 B** | 其中 177 B 是**明文 JSON**：`{"format_version": 1, ... "ideal_urate": [{"Conv": "100.00"}]}` |

-> **dump 只给尺寸与层序，不给偏移**；偏移要从产物量（[`tools/bbmap.py`](../tools/bbmap.py)）。

**结构 / 调试视图**

```bash
./tools/compile.sh ops/fc_1x64x64_int8/model.tflite /tmp/x.dla \
  --show-exec-plan --show-memory-summary --show-l1-req
```
-> 编译日志里给出执行步、层清单、DRAM（Input/Output/Temp/Static/Code）与 L1 需求。这是**最便宜的结构证据**。

```bash
./tools/compile.sh ops/fc_1x64x64_int8/model.tflite /tmp/x.dla \
  --gen-debug-info --gen-urate-info --verbose
```
实测（`fc_1x64x64_int8`，同一模型）：plain **7532 B** / `--gen-debug-info` **8088 B**（+556）/ `--gen-urate-info` **7818 B**（+286）/ `--show-l1-req` 7546 B。
-> 调试信息 / urate 信息确实**写进 `.dla`**（体积可见）。**06 起已判可读性**（§2.1）：
`.dla` 尾部嵌了完整命令行，所以 `ΔB` 里有 `len(开关文本)+1` 是回显；扣掉后 debug 真写 **539 B**、urate 真写 **269 B**、`--show-l1-req` 真写 **0 B**。

```bash
./tools/compile.sh ops/fc_1x64x64_int8/model.tflite /tmp/x.dla --check-target-only   # 只判目标支持
./tools/compile.sh ops/fc_1x64x64_int8/model.tflite /tmp/x.dla --show-builtin-ops    # 支持的算子表
./tools/compile.sh ops/fc_1x64x64_int8/model.tflite /tmp/x.dla --show-mtkext-ops     # MTK 扩展算子表
```

**权重外置（本次最重要的发现）**

```bash
./tools/compile.sh ops/fc_1x64x64_int8/model.tflite /tmp/fc_extract.dla \
  --extract-static-data /tmp/fc_static.bin
```

实测（见 [`reports/compiler-blackbox-02.md`](../reports/compiler-blackbox-02.md)）：
`.dla` **7545 -> 3666 B**，权重变成**第 2 个输入张量**（4096 B），喂回原始权重后输出与参考**逐字节相同**。

**形状 / 动态形状**

```bash
# --resize 必须给**全部输入**的尺寸，逗号分隔、按输入顺序；少给一个就直接 EXIT=1
./tools/compile.sh ops/add_1x64_int8/model.tflite /tmp/add_resize.dla --resize 1x128,1x128

# --runtime-dynamic-shape 单独用没有可见效果（见下）
./tools/compile.sh ops/add_1x64_int8/model.tflite /tmp/add_dyn.dla --runtime-dynamic-shape
```

实测（`add_1x64_int8`，两输入）：`--resize 1x128,1x128` 编出的 I/O 表是 `[1,1,1,128]`，喂 128 B 输入、输出与「重新抓的 128 资产」**逐字节相同**；
`--resize 1x64,1x128` 会 EXIT=1（`Fail to run ResizeInputsPropagationPass`）。
`--runtime-dynamic-shape` 能编过，但 I/O 表仍写死 64 B，喂 128 B 报 `The size of input[0] should be 64` —— **它自己不能让一份产物吃多种尺寸**。

**其他**：`--dla-metadata key:file,...`（外部元数据）、`--gno NDF,SMP,BMP`（图优化）、`-e/--exec`（编译器自己跑推理）。

## 3. 容器：`.dlb` 而不是 `.dla`

```bash
S=/mnt/d/deepseek_ workspace/mtk/neuropilot-sdk-basic-7.0.8-build20240807/neuron_sdk/host
LD_LIBRARY_PATH=$S/lib $S/bin/dla-packer -o /tmp/fc.dlb ops/fc_1x64x64_int8/model.dla
LD_LIBRARY_PATH=$S/lib $S/bin/readdlb /tmp/fc.dlb
```

实测输出（原文）：

```text
DLA List:
 #0: <path>/model.dla

DLB Functions:
 * Legacy Static Data Extraction: OFF
 * Generated by extracted-shared: OFF
 * DRAM Temporary Buffer Sharing: OFF

DRAM temporary buffer (unit: byte):
```

打包体积：level 0 = **7899 B**、level 9 = **5831 B**（源 `.dla` 7545 B）。
另一组实测（`fc_a`，源 `.dla` 7635 B）：level 0 = **8003 B**、level 9 = **5858 B**（0.732×）；level 3 / 5 / 9 在 7561 B 的样本上给出**同一个大小**（5756 B）—— 这档压缩到 level 3 就饱和。
打包入口统一走 `tools/pack.sh <level> <in.dla> <out.dlb>`（记录 cmd/rc/size/sha，并顺带把 `readdlb` 的原文留在 `.pack.log` 里）。

注意：`readdlb` 打印完这些信息后**以 SIGABRT 退出**（rc = -6），输出本身是完整的 —— 记在这里，别当成自己失败。

## 4. `mdla-bwhint -d`：`.dla` 里的 JSON 元数据（06 补）

help 原文：`mdla-bwhint [OPTION...] hint dla` —— 位置参数**永远是两个**，`-d` 时第一个是**输出**的 hint 文件。

```bash
S=/mnt/d/deepseek_ workspace/mtk/neuropilot-sdk-basic-7.0.8-build20240807/neuron_sdk/host
LD_LIBRARY_PATH=$S/lib $S/bin/mdla-bwhint -d /tmp/v0.hint ops/_probe/bb06-dump/v0.dla   # rc=0，115 B

{"format_version": 2, "graphs": [{"subgraphs": [{"codes": [{"flows": [{"bw_index": 0}]}], "target": "MDLA_5_0"}]}]}
```

**encode → dump 往返**（证明这段是官方可读**可写**的）：

```bash
$ echo '{"format_version": 2, "graphs": [{"subgraphs": [{"codes": [{"flows": [{"bw_index": 7}]}], "target": "MDLA_5_0"}]}]}' > /tmp/hint.json
$ $S/bin/mdla-bwhint /tmp/hint.json v0.dla -o /tmp/encoded.dla      # rc=0，仍 7561 B
$ $S/bin/mdla-bwhint -d /tmp/back.json /tmp/encoded.dla            # rc=0
{"format_version": 2, "graphs": [{"subgraphs": [{"codes": [{"flows": [{"bw_index": 7}]}], "target": "MDLA_5_0"}]}]}
```

- 基线 / `--gen-debug-info` / `--gen-urate-info` 三个产物 dump 出的内容**完全相同**（`bw_index: 0`）
  —— `-d` 读的是**带宽提示段**，不是 debug/urate 段；
- `readdlb` 对三种产物输出**逐字相同**（只有容器级三行状态），不看 debug/urate；它的退出码是 **134（SIGABRT）**，输出本身完整；
- 证据：`ops/_probe/bb06-dump/readers.txt`。

## 5. `neuronrt -d`：资产契约的第一手来源

```bash
neuronrt -m hw -a <run>/f.dla -d
```

实测（`--extract-static-data` 后的 FC）：

```text
Input :
	Handle = 0, <1 x 1 x 1 x 64>, size = 64 bytes
	Handle = 1, <1 x 1 x 64 x 64>, size = 4096 bytes
Output :
	Handle = 0, <1 x 1 x 1 x 64>, size = 64 bytes
```

这条命令把「有几个输入、什么形状、多少字节」直接印出来 —— 以后写 plan / 抓资产先跑它，比猜快得多。

## 6. 适用范围与未解

- 本文只覆盖 **host 侧工具**；芯片侧（`mt6897/bin`）是 aarch64，只能在设备上跑。
- `extract-shared` 无 `--help`，行为未探。
- `--extract-static-data` 生成的侧文件是 **262,178 B**（远大于 4096 B 权重），`neuronrt` 并不消费它（它要的是 4096 B 原始权重）—— **这个文件是什么，未知**。
- `--resize` 的结构副作用已测（[`06`](../reports/compiler-blackbox-06.md) §4.4）：`.dla` 本体 −16 B、dump 的 `Input/Output` 变 128、`Code` 400→384；`--runtime-dynamic-shape` 仍只有 02 的行为结论。
- `--gen-debug-info` 那 539 B 的**字段 schema** 未解（结构可辨认、无官方 host 读取器）；`neuronrt -d` 能正常读这份 `.dla`，但只印 I/O。
- `--dla-metadata` 的段内布局未解（只知道本体 +90 B 且 note 原文在内）。

## 7. profiling：真正的出口是 `-P<n>` + `MTKNN_*`（07 补）

> 结论来源与全部实测：[`07`](../reports/compiler-blackbox-07.md)。这一节只放**能直接抄的命令**。

### 7.1 `-P<n>` / `--profiling-level=<n>`：编译期打等级（`--help` 里没有）

```bash
./tools/compile.sh ops/_probe/bb07-prof/build/fc.tflite /mnt/d/bb07-tmp/x.dla -P3
# 等价： --profiling-level=3        （等级 1..3；-P1/-P2 只多 ~16 B，-P3 才是全量）
```

- 产物尾部仍然嵌命令行，所以 `ΔB` 里有回显；扣掉后 `fc_1x64x64_int8` 的 **-P3 真写 +707 B**（`--gen-debug-info` 是 +539 B，两者不是一回事）；
- **-P3 的写入量随层数走**：Qwen2.5 decoder layer（48 层）`3,754,640 → 3,809,342 B`（**+54,702**）；
- **`--gen-debug-info` 不满足任何 profiling 等级**（运行时仍报 `DLA only supports 0`）——06 那句 help 有误导性。

### 7.2 运行期：`MTKNN_ENABLE_PROFILER` + `MTKNN_PROFILING_LEVEL`

```bash
adb shell "cd /data/local/tmp/npuops && \
  MTKNN_ENABLE_PROFILER=1 MTKNN_PROFILING_LEVEL=3 \
  ./bin/neuronrt -m hw -a bb07/full_p3.dla -i bb07/din.bin -o bb07/o.bin -c 5"
```

等级门槛（实测原文）：

```text
DLA 无 -P, ask=3 -> WARNING: To enable profiling level 3, please use -P3 option to re-compile the model
DLA -P1,   ask=3 -> WARNING: The runtime profiling level is 3, but DLA only supports 1   (随后自动降到 1)
DLA -P3,   ask=3 -> INFO: The profiling level is now set to 3
```

产出：

| 等级 | 控制台 | 文件（CWD 或 `MTKNN_PROFILER_LOG_PATH=<dir>`） |
|---|---|---|
| 1 / 2 | 阶段级摘要表（`Runtime Status (LEVEL 1)`、`Detail of 'Inference' (LEVEL 2)`） | 无 |
| **3** | 同上（**板端只写文件、不打印表**） | `dla_info.json`（21 KB）+ `execution_result.json`（**272 KB**） |

`execution_result.json` 的形状：`inference -> codes[每核一个] -> flows[每条命令一条]`，每条 flow 带 `endCycle` 与 14 个 PMU event；
`dla_info.json` 把同样的 flow id 映射到 `opIndices[]` 与 `bufferAccesses[{buffer_id, offset, size}]`——**这就是每层的耗时与带宽来源**。

### 7.3 每命令的耗时/带宽怎么算（07 实测，`full_p3`）

```text
最慢核 endCycle 263906，另一核 189009；运行时 exec_us = 264 µs  ->  263906/264µs = 999.6 MHz ≈ 1.0 GHz
us = cycles / 1000；带宽 = 该 flow 的 bufferAccesses 字节和 / us
```

| 核 | 命令 | 算子 | µs | 占该核 | 带宽 |
|---|---|---|---|---|---|
| 1 | 2 | FULLY_CONNECTED（q_proj） | 90.8 | **34.4%** | 18.0 GB/s |
| 1 | 71 | FULLY_CONNECTED（o_proj） | 69.3 | **26.3%** | 23.6 GB/s |
| 0 | 13..19 | SPLIT+CONCAT（14 头 KV 复制） | 各 ~1.5 | 各 1.5% | 0.18 GB/s |

- **每核 sum = 运行时 `exec_us`**（判据达成）；但 **≠ `neuronrt -c N` 的墙钟**：`full_p3` 墙钟 692–1066 µs，设备侧只占 **25–38%**；
- 观测开销：level 1 = 1.35、level 2 = 1.73、**level 3 = 9.74 ms/inf（7.2×）**；
- ⚠️ **level 3 跑完板子会进 `MDLA timeout` 坏态**（`ret=-5`、`time=25s`，连 known-good 算子都失败，需 reboot）。跑前后各一次 `tools/healthcheck.sh --quick`。

### 7.4 自建 harness：拿 `getProfiledQoSData`（每 sub-command，非每层）

```bash
bash ops/_probe/bb07-prof/build-profqos.sh host          # x86 冒烟（-m null 会除零，harness 已兜底）
bash ops/_probe/bb07-prof/build-profqos.sh device-vendor  # aarch64，链板子自带的 /vendor/lib64 运行时
# 板上： ./bin/profqos_v <dla> -i in.bin -o out.bin -c 20
#    -> [subgraph 0] subcmds=1 / cmd 0 exec_us=264 bandwidthMBps=0
```

**粒度警告**：这颗 MDLA 上整图就是**一条命令**（`subcmds=1`），所以公开 API 只给 1 个数；每层必须走 §7.2 的 level-3 JSON。
