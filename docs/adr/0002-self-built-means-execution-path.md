# "自建"= 自建执行路径，命令先捕获、后自生成

**Status**: accepted

仓库现状：自建提交器没有命令生成器，它重放从厂商 runtime 抓下来的 cmdbuf，靠地址打补丁定位（`docs/OWN-SUBMITTER.md:337`「只重放了 cmdbuf、从未加载代码段」）。新形状意味着**重新捕获一次资产**，因为形状烘死在命令流里（`docs/OWN-SUBMITTER.md:65`）。真正的命令自生成需要 MDLA5.0 ISA，是 `PLAN.md:165-176` 里尚未开始的那一步。

本阶段把"自建"定义为**自建执行路径与调度**：自己完成 handshake / 分配 dma-buf / 提交 / 同步，命令仍借自厂商编译产物。命令自生成单列为一个后续阶段，不混进当前里程碑。

**Considered Options**
- 直接啃 ISA 造反汇编生成器：最彻底，但在 Qwen2.5 的形状还没跑通之前，等于同时攻两个未知
- 继续用厂商 runtime 跑完整网络：最快，但就不存在"自建"这件事了

**Consequences**
- "自建"这个词必须带定语，否则口径会漂：**执行路径自建 ≠ 命令自建**
- 形状一变就要重新捕获，Qwen2.5 每层多种形状会让捕获资产数量膨胀，资产复用的粒度迟早要单独设计
- 常量权重在自建提交器上的那个 IoVA 契约（`docs/OWN-SUBMITTER.md:317-339`）依然悬着：本阶段走 DLA 路径不受它影响，但迁移时必须重开决策
