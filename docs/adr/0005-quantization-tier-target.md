# 量化档目标：先做 4W8A，目标形态采用「attention 4W16A + MLP 4W8A」的混合

**Status**: accepted

厂商 LLM runtime 的出厂档是 `asym4W_sym16A`（w4a16）。但本机实测（`skills/mtk-llm-pipeline/references/02-quantization-matrix.md`）在同样 4-bit 权重下，w4a8 的 decode 是 **5.94 ms**、w4a16 是 **11.6–14.5 ms**（慢约 2 倍）；4-bit 的质量本身也可疑（device token match 23/268，加 hessian 只到 28/268）。厂商文档的推荐列表只有 `sym4W_sym16A` / `asym4W_sym16A` / `dynamic_quant`，4W8A 不在其中，但明确允许 attention 用 4W16A、MLP 用 4W8A 混用。

因此：**先做 4W8A**（本仓库已有板端证据：int4 权重 + int8 激活单执行步、0/64 逐位），**目标形态是厂商允许的混合**（attention 4W16A + MLP 4W8A）。4-bit 档**不承诺逐位**——厂商自己声明 device 4W16A 不是 bit-true，我们的探针也测到 int4 解压后 ≤1 码抖动。

**Considered Options**
- 全局 4W16A：与厂商默认一致，但速度只有 w4a8 的一半，且质量并未因此变好（23/268）。
- 全局 4W8A：最快，但 attention 的分数分布在 4-bit 激活下抖动会被 softmax 放大（T=128 实测 probs 已有 ~12% 抖动）。
- W8A16F（dynamic quant）：质量接近 fp32，但 decode 15.08 ms、内存 2×，不适合作为主档。

**Consequences**
- 判据升级为两层：算子级 `|Δ| ≤ 1 码` + `cosine ≥ 0.9999`；整网级看 token 命中率/困惑度，**不看逐位**。
- golden 必须按「量化契约」实现（两次舍入 + M0 取整规则），否则 ±1 码会被误读成实现错误。
- 混合精度图意味着每条 dtype 缝要显式写 DEQUANTIZE（ncc 已实测：原生层、不 bridge、每缝 +1 层）。

## 实测订正（2026-11-13，票 q04 之后）

4W8A 的整层实测把本 ADR 的两条判据逼到了墙上：

- **组件级全部逐位**：4W8A 的 FC 投影、SwiGLU、BMM-QK、BMM-PV 板端与量化 golden **0 码**（per-channel int4 + int32 per-channel bias 可编、单执行步）。int8 RMSNorm 是例外：**861/14336、max 2 码**（eps 那层被折掉，仓库对该链的预算是 4 码——保留 FAIL，未改阈值）。
- **整层不达判据**：61 层 / 单执行步 / Static 7.2 MiB / 噪声 0，但 device vs 量化 golden **均值 4.13 码、max 41**；device vs 独立 fp64 链 **cosine 0.9107**，而量化 golden vs fp64 已经是 **0.9130** ⇒ **设备是忠实的，差距全在量化**。
- **误差归因**：int4 每通道权重 **每矩阵 14.0–15.8%**（主项；MLP 无 bias 藏不住），int8 激活 2.4%（次项）。掉码从 `probs` 开始：int8 分数 1 码 = 37，softmax 在近并列 row 上翻转 17/224。

因此本 ADR 追加三条：

1. **「算子级 cosine ≥ 0.9999」只适用于 8-bit 及更宽的档**。4-bit per-channel 在本栈（TFLite 只有 per-channel，没有 group-wise scale）**达不到** 0.9999，这是量化方案的性质，不是实现错。4-bit 档的算子级判据改为：**device == 量化 golden（码级 0 / ≤1）** + **device 与 golden 的 cosine 差 ≤ 0.003**（本票实测 0.9107 vs 0.9130 = 0.0023，说明设备忠实）；质量由整网/端到端判据回答。
2. **4-bit 的质量缺口要从「量化方案」解决，不是从「精度档」解决**：厂商的 4-bit 是 GPTQ/hessian + 分组 scale（他们的 bin 体积 0.5075 B/param ≈ 4bit + 1.5% scale，反推每 32–64 个权重一个 scale），而 TFLite per-channel 只有每输出通道一个 scale —— 这一条差异就能解释 14–16% 对厂商 4-bit 的差距。**下一步先查「分组 scale 能否在本栈表达」与「8W8A 的中间档是否够用」**，再决定锁哪个档。
3. **落档顺序改为：等 04b/04c 的结果再定**。若 group-wise 不可表达而 8W8A 的质量可接受，则主档改 **8W8A**（速度 8.09 ms、内存 2× 4W），混合精度（attention 与 MLP 分档）作为次选；若两者都不行，则回到 fp16 + 只在能证明不掉质量的位置用 4-bit。

三个必须记住的负结果（都有最小复现，见 `docs/OP-w4a8-layer.md`）：
- **int8 掩码 SOFTMAX 编不过**（无 exec plan；−4096 在 int8 分数域不可表示）→ 该层走 fp16 缝（+2 层）。
- **int8→int8 `QUANTIZE` 能编但算错**（rel_l2 0.85；去掉它就对 9e-5）→ 后续票不要用显式 QUANTIZE 做 requant。
- **T=8 的 P·V 被 16 B 行规则挡住**（EXIT=1）→ 4W8A 整层取 T=16。
### 第二次订正（2026-11-13，票 q04c 之后）：天花板在**激活**，不在权重

把 4W8A 的 harness 换成 8W8A（只换权重位宽，图/缝/T 一字未改）后，四个数把问题定死了：

| 项 | 4W8A | 8W8A |
|---|---|---|
| 每矩阵权重量化误差 | 14.02–15.83% | **0.772–0.873%**（18× 改善，逐位复现） |
| 只量化权重（fp64 链）的 cosine | — | **0.9998451** |
| 整层 device vs fp64 链 | 0.9091 | **0.9649** |
| 段级：`scores → probs`（**不经过任何权重**） | 0.9541 | 0.9606 |

结论：**权重侧在 int8 就已经不是瓶颈**（0.99985）；把权重从 4-bit 换成 8-bit 只把整层从 0.909 拉到 0.965，剩下的 0.035 全在**激活的 int8 量化**（softmax 近并列 row 翻转，int8 分数 1 码 = 37）。

所以本 ADR 的档位优先级改写为：

1. **主档 = 4W16A**（int4 权重 + **int16 激活**）——它同时是 (a) 厂商的出厂格式、(b) 唯一可能越过 0.9999 的形态（激活是 int16 就没有 probs 的 1 码=37 问题）。待票 04d 用同一 harness 量出整层 cosine 验证；
2. **4W8A / 8W8A 只作为「快档」**：8W8A 的整层 ceiling 是 **0.9649**（已实测），4W8A 是 **0.9091**；两者的差别几乎全在权重（14% vs 0.8%），而激活是共同的 0.96 天花板。任何声称「4-bit/8-bit 激活能达到 fp16 级别」的说法都应被这两条数字驳回；
3. **分组 scale（group-wise）的价值收敛为「省内存」**：权重误差从 14% 降到接近 int8 的水平，可以让 4-bit 权重在 int16 激活下不再拖质量，但它**不能**改善激活侧的天花板。所以它是优化项，不是质量前提。

代价参照（同会话交替测量）：8W8A 的 `.dla` 是 4W8A 的 **1.98×**、Static 7.2M→14M、板端单层 1.44→2.17 ms/inf。

顺带记录两处上游口径订正（票 04c 发现并留痕）：票 04 的 `bmm_qk` cosine 应为 0.9999566（0.9999013 是整层 `scores` stage 的值）；票 04 的权重码有两份分母（float32/float64），统一到 float64 后 4W8A 整层 golden 位移 4.1e-4（cos 0.9130→0.9134），两档同口径重测。
### 第三次订正（2026-11-13，票 q04b 之后）：分组 scale 不是答案，厂商的增益在转换器

票 04b 把「分组 scale 能不能救 4-bit」彻底问清了：

1. **属性级不可表达**：TFLite 只有一个 `quantized_dimension`。给 896 宽 int4 权重喂 1792 个 scale、或把 `quantized_dimension` 改成 1，都在**加载期**被拒（`Fail to process the given model`）；ncc 没有分组开关，`MTKEXT_*` 只是同批算子的包装；`--import_qparams_config_file` 属 MTK 转换器的**输入**端（TFLite 是它的输出），导不进我们自己构造的图。
2. **K 切段的等价分解能表达、且设备逐位**（`ops/q04b_fc_g{2,4,8}`：EXIT=0、1 执行步、板端 0/14336），代价是每矩阵 **2G−1 层**（整层 61 → 83/119/**191**，1.36×/1.95×/3.13×，仍单执行步）。
3. **但它救不了 4-bit**：权重 rel_l2 17.6%→13.2%(G=8)→7.6%(G=128)，而整条 int8 链是 0.866/0.820/0.856——**没有改善**。原因是每个部分和都要落回 int8（没有 int32 输出，int8→int8 的 `QUANTIZE` 已被票 04 证明算错），√G/2 码的舍入把增益吃光，两条曲线在 G≈16 交叉。
4. **厂商的分组比我猜的大得多**：bin 体积差 3,757,056 B / 493,961,216 参数 = 0.76% ⇒ 每 **256** 个权重一个 scale（不是先前推断的 32–64）。K=896 对应 G≈3.5，权重误差 ~15%——**与 per-channel 同量级**。所以他们 4-bit 比我们好，靠的不是分组 scale，而是转换器里的 **hessian / AdaRound / Bias Correction**（`transformer*.so` 里实测有 `use_hessian_opt` / `hessian_opt_block_size`）。

顺带一条**改写判断的对照**：用真实 Qwen2.5-0.5B 权重离线跑 8W8A 单层，cosine **0.9999157**（rel_l2 1.3e-2、probs 0.9999960）——而夹具权重下同一档只有 0.9649。这说明**夹具比真权重苛刻**（embed 行输入 + 大 bias 造成的极端分数分布），所以「激活天花板 0.96」可能是夹具性质，不一定是真实限制。**档位必须用真实权重在设备上再验一次**（票 04e）。

方法论教训（已进 NOTES）：校准类实验的校准集与评估集必须分开——在「校准行」上自评给出 0.003 的假改善（16 行拟合 896 列的陷阱），留出集上的真实改善只有 0–20%。

### 第四次订正（2026-11-13，票 q04e 之后）：**真权重比夹具更差**；0.9999157 是「只量化权重」的口径

第三次订正用「真实 Qwen2.5-0.5B 权重离线跑 8W8A 单层 = 0.9999157」推出了「夹具比真权重苛刻」。票 04e 把这一条拆开重测
（同一 harness、同一 per-channel 规则、同一 T=16 seam、同一批 token 的 embed 行作输入，只换权重来源；板端全部持锁，两档噪声底都是 0 码）：

| 口径 | 夹具权重 | 真权重 |
|---|---|---|
| 只量化权重（激活 float64，`--wq-chain`） | 0.9998451 | **0.9999157** ← 第三次订正引的就是这一格 |
| 整条 int8 激活链，量化 golden vs fp64 | 0.9673771 | **0.8737825** |
| 整条 int8 激活链，**device** vs fp64 | 0.9649298 | **0.8801239** |
| `probs` 段 device vs fp64 | 0.9580252 | **0.7676888** |
| 每矩阵 int8 权重误差 | 0.772–0.873% | **0.828–1.140%** |
| 输入 int8 per-tensor 激活误差（n1） | 2.3944% | **5.9531%** |
| `.dla` / Static / 层数 / 执行步 / 噪声 | 15,089,161 B / 14M / 61 / 1 / 0 | 15,089,171 B / 14M / 61 / 1 / 0 |
| 板端单层（同会话交替，`-c 30`） | 1.87–2.28 ms/inf | 1.71–2.20 ms/inf |

三条结论：

1. **0.9999157 不是 8W8A 的数字，是「8-bit 权重 + 精确激活」的数字**。把激活按真实部署做 int8 per-tensor 量化后，
   真权重整层 **0.8801**（设备）/ 0.8738（量化模型），比夹具的 0.9649 还差 0.085 —— **夹具不是悲观估计，它是乐观的那一个**。
   第三次订正对档位的方向性判断（主档 4W16A、8W8A 只作快档）**不变**，但理由要改：不是「夹具把 int8 激活显得很差」，
   而是「真权重的激活动态范围让 int8 per-tensor 激活更差」（`|n1|max` 1.05→2.92、`|scores|max` 4.7e3→1.25e4）。
   消融（真权重×夹具输入 / 夹具权重×真输入）证明主因是**权重**，不是输入。
2. **权重从来不是瓶颈，激活位宽才是**：int8 per-channel 权重 0.83–1.14%，只量化权重 0.999916；per-tensor int8 激活
   在真权重上是 5.95%（夹具 2.39%）。要过 0.9999 只能动**激活位宽或粒度**，与「主档 4W16A」一致；但**04d 的 4W16A 必须在
   真权重上复测**——真权重把 `scores` 推到 1.25e4，现有 fp16 seam 在 `scores/8 ≈ 1.5e3` 处 1 ULP ≈ 0.98，softmax 输入被量化到
   1.0 的台阶上（这一条在 golden 里就能看到，不需要设备）。
3. **「设备忠实 ≤0.003」是夹具量级上校的界**：真权重整层 `abs(Δcos)` = 0.0063、`probs` 段 0.063、真权重+夹具输入 0.0520，
   全部超界；但方向都是 **device 比量化 golden 更接近 fp64**（elementwise int8 段按「每步 per-tensor 重舍入」建模，
   真权重动态范围下这个模型偏悲观）。⇒ 真权重上判断设备准不准要读 device 列，这个界需在真权重上重定（未做）。

证据与复现命令：`docs/OP-8w8a-real.md`（`ops/decoder_layer_t16_w8a8_real`、`ops/_w8a8_real_bisect/*`）。

### 第五次订正（2026-11-13，票 q04f 之后）：真权重四格矩阵——**8W16A 是唯一近标档，仍差 4e-5**

票 04f 用同一 harness 在**真权重 / 真输入**上补齐了二维矩阵（12 张图 + 6 次板端，锁内，噪声底 0 码），
并把 04e 的一处 harness 缺陷修掉（见本条末尾）：`docs/OP-tier-matrix.md`。

| device vs 独立 fp64 链（T=16，f16 缝） | 4W8A | 4W16A | 8W8A | **8W16A** | 8W16A（native 缝） |
|---|---|---|---|---|---|
| 整层 cosine | 0.8775767 | 0.9732673 | 0.8971126 | **0.9998311** | **0.9998598** |
| `scores` / `probs` | 0.99975 / 0.74768 | 0.99999 / 0.99864 | 0.99976 / 0.75588 | 0.9999998 / 0.99970 | 0.9999998 / **0.99989** |
| ｜Δcos(device, golden)｜ | 0.0066 | 0.0000 | 0.0178 | 0.0001 | 0.0000 |
| `.dla` / Static / 层数 | 7.63 MB / 7.2M / 61 | 7.73 MB / 7.3M / 61 | 15.09 MB / 14M / 61 | 15.10 MB / 14M / 61 | 15.11 MB / 14M / **60** |
| 板端单层（中位） | 1.43 ms | 2.20 ms | 1.81 ms | 2.16 ms | 2.16 ms |

四条结论：

1. **8W16A 不达 0.9999**（差 6.9e-5 / 4.0e-5），但它是四格里唯一进入 1e-4 量级的档。
   1−cos 预算（native 缝）：int8 per-channel 权重 **8.43e-5（84%）**、int16 激活 +1.0e-5、
   器件定点链路 +4.59e-5，合计 1.402e-4 对判据 1.0e-4。
   ⇒ **在 int8 权重下 0.9999 只剩 1.6e-5 给激活与器件，结构上过不去**；要过只能动权重侧
   （fp16/16-bit 权重、group-wise、hessian），不是再加激活位宽。
2. **主档建议 = 8W16A + native 缝**（60 层、15.1 MB、2.16 ms；`probs` 比 fp16 缝高 2e-4）。
   **4W16A 不能当「省内存备选」**：真权重 0.9733 = int4 per-channel 权重天花板（`--wq-chain` 0.9733031），
   04d 的「激活天花板搬走了、天花板在权重」在真权重上复现，但它离 0.9999 有 0.027。
3. **4-bit 彻底退出主档**；8W8A 也不可用（0.8971）。主档只可能是 8W16A，或「8W16A + 更宽的权重」。
4. **判据需要拍板**：ADR 的「算子级 cosine ≥ 0.9999」用在**整层**时，int8 权重只剩 1.6e-5 余量，
   而器件舍入一项就是 4.6e-5。要么把档位判据按实测改成 `≥0.9998` 并写清它和算子级判据的区别，
   要么明确「0.9999 必须配 16-bit/fp16 权重」。本 ADR 不擅自改判据。

**同时订正第四次订正的一处读数（harness 缺陷）**：RoPE 的两半 `lo/hi` 各用各的 scale，而
`CONCATENATION` 只声明一个输出 scale ⇒ 真权重下（|hi|max 80.59 vs |lo|max 51.13，差 1.576 倍）
hi 半被低估并被 int16 截断 0.22%，`q3` 段因此只有 0.9747（夹具尺度比 1.0003，所以 04c/04d 没被影响）。
修好（两半共用一条 scale + `q_concat` golden 按输入 requant，设备语义实测逐码到 4 码）后 `q3` = 0.9999999。
**04e 的 8W8A 真权重读数因此上移：device 0.8801239 → 0.8971126、golden 0.8737825 → 0.8792696**
（方向不变：真权重依然比夹具差，差距 0.085 → 0.068）。夹具回归位移 ≤0.002。
证据与复现：`docs/OP-tier-matrix.md`（`ops/decoder_layer_t16_w{4,8}a{8,16}_real*`、`ops/_tier_matrix/*`）。
