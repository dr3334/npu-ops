# CAPABILITY —— FULLY_CONNECTED（int8）的能力边界图

采集：2026-11-12 · ncc-tflite 7.3.15 / `--arch=mdla5.0 --disallow-bridge` · 板 Titan 1（MT6897/MT8792）。
方法：逐形状生成 TFLite → 编译 → 记录**失败阶段**（`tools/scan_shapes.sh`，原始表 `docs/CAPABILITY.tsv`）。
**网格规模 ≠ 通过数量**：下表是"扫过的形状"，不是"支持的全部形状"。

## 1. 规则（由实测数据归纳，附适用范围）

| 维度 | 观测 | 结论（附边界） |
|---|---|---|
| K | 8/24/40/56/72 编译 **失败**（`Bridging is disallowed but gap is detected`）；16/32/48/64/80/112/128/192/256/384/512 **通过** | **K 在图的边界张量上须是 16 的倍数**（见 §9.1：16 B 规则只约束边界张量，中间张量不受此限，`[T,1]` 行宽 2 B 也可编）。非 16 倍数不是"运行错"，而是编译器直接判失败 |
| N | 8/16/24/32/48/64/96/128/192/256/384/512 **全部通过** | N 无 16 倍数约束（8 也可） |
| M | 1/2/7/8/31/32/127/128 **全部通过** | M 无对齐约束（7/31/127 这类尾块可编） |

> N=8 与 M=7/31/127 能**编译**，并且抽样在板上**跑通且数值正确**（见 §3）。
> 这不等于任意 M/N 组合都成立——组合空间没有全扫。

## 4. 失败分类

| 失败阶段 | 现象 | 含义 |
|---|---|---|
| **编译期** | `Bridging is disallowed but gap is detected between Input and MDLA_5_0` | 该形状需要 CPU 桥接（不是 NPU 能力边界，而是"我们策略不接受桥接"） |
| **运行期** | `There is a runtime error during inference` | 编译通过但执行被拒（E-105B 里把 `num_subcmds` 改成 0 就属于这类） |
| **数值** | `max_abs_diff > tol` | 只有 requant 边界的 ±1（见 E-003） |

## 5. 未覆盖（必须明说）

- 只扫了 **M×K×N 的单独轴**，没有扫组合（例如 M=128 且 K=8）；
- 只测 **int8**；fp16 只测了 2 个形状；fp32 不可直连（E-004）；
- 只测 **FULLY_CONNECTED**，其它算子见 W5；
- K 的上界未触及（512 通过，未测更大）；
- 未测非 4 维输入、batch>1 的 4D 形态。

## 6. 跨算子统一规则（来自 W6 并行工作的合并）

三个 worktree 的独立结论最后收敛到同一条**字节对齐**规则上：

> **`--disallow-bridge` 下要无桥编译，DRAM 边界张量的最内层行必须 ≥ 16 字节，且字节数必须是 16 的倍数。**
> 这是**字节**规则，不是元素规则；并且**输入侧**最严格，输出侧在部分算子上可以更小。

| 来源 | 证据 |
|---|---|
| FULLY_CONNECTED（本文 §1） | int8 的 K 就是行字节数：K=8/24/40/56/72 失败，16/32/48/64/80/112 成功 —— 正好是"K % 16" |
| 激活/归约（`docs/OP-actreduce.md`） | fp16 w8（16 B）✅ vs int8 w8（8 B）❌；int8 w16/48 ✅、w40/44/56 ❌；MEAN `[1,8,12]` fp16 失败——**总字节 192 也不行，看的是每行** |
| 形状/布局（`docs/OP-shapeops.md`） | 同一算子只改边界行宽：8 B → `IN_GAP`/`OUT_GAP`，16 B → 通过且逐位相等 |

失败原文（可直接检索）：

```
IN_GAP  = "Bridging is disallowed but gap is detected between Input and MDLA_5_0"
OUT_GAP = "Bridging is disallowed but gap is detected between MDLA_5_0 and Output"
```

**注意**：失败的模型**仍会先打印 `Layer<Target: MDLA_5_0>` 的 exec plan**（bridge 检查在打印之后），
所以判断成败必须看 `EXIT=`，不能只看层名。

## 8. 构建产物的可复现性（重要）

`model.tflite` 是**字节可复现**的（同源重建 sha 相同）；**`.dla` 不是**——同一个 tflite 连续编译 3 次，
大小相同但 sha256 三次都不同。因此：
- `.dla` 的 sha256 只能标识"这是一个产物"，**不能**当作构建一致性/回归比对的依据；
- 回归要比对的是**数值**（`compare.txt`），不是 `.dla` 哈希。

## 9. 由 W6b 修正/收紧的规则

1. **16 字节规则只约束 DRAM 边界张量**（rms-agent 的对照实验）：`[T,1]` 这类中间张量行宽 2 B 也能编译运行；
   失败的只有"图的输入/输出"这一侧。原文的"输入侧最严"要读作"**边界**最严"。
2. **int8 路径会把小于 1 个 code 的 `+eps` 常量折叠掉**（RMSNorm int8 的 `ElementWiseAdd` 层消失，
   层号从 <1> 跳到 <3>）。⇒ int8 RMSNorm 实际上**没有 eps**；`mean=0` 的行为未测，标 UNKNOWN。
3. **RSQRT 是原生 MDLA_5_0 层**（fp16 与 int8 都落 MDLA，int8 甚至逐位），
   所以 RMSNorm 不需要 CPU 侧求倒数：6 个算子组成的链在**同一个执行步**里跑完。
4. fp16 存 eps 只有约 0.6% 精度（`1e-5 → 1.0014e-05`，次正规数）——写 golden 时要按 fp16 舍入，不能按 float32。
