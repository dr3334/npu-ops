# 黑盒研究 04：FC-A…FC-E 控制变量矩阵（只动一个维度）

日期：2026-11-14 · SDK 7.0.8 / `ncc-tflite` 7.3.15 · 纯离线（只编译 + 文件差分，未上板）
票：`04-controlled-experiments.md` · 规格：[spec.md](../.scratch/compiler-blackbox/spec.md) ·
上一票：[03](./compiler-blackbox-03.md)（工具与噪声标定方法）

## 0. 一句话

用 03 的 `tools/bbdiff.py` + **新矩阵** `tools/bbdiff-matrix-blackbox04.json` 跑了 FC-A…FC-E 九个变体
（每变体编译 9 次、保留 5 次同类别产物）：**N/K/权重三类变化全部落在可解释的区段**，
而**只改量化配置**的两条给出了本票最有信息量的结果 —— 改 requant 比值只动**一个字节**（偏移 6343），
改 scale 的**绝对大小**（比值不变）则**一个字节都不动**；顺带**修正了 03 票「权重未重排」的说法**：
权重区仍是精确 4096 B，但块内是同一组码值的**重排**。

## 1. 怎么跑

```bash
# WSL（/usr/bin/python3 里有 numpy/flatbuffers/tflite schema）
wsl.exe -e bash -c "cd '/mnt/d/deepseek_ workspace/mtk/wt-bb04' && \
  /usr/bin/python3 tools/bbdiff.py --matrix tools/bbdiff-matrix-blackbox04.json"
```

单次全跑 ≈ 30 s（9 变体 × 9 次编译）。退出码：0 = 所有 check 符合预期；1 = 有 check 不符。
**本次退出码是 1**，原因见 §4.4：两条预注册假设被实验推翻、另有两条工具阈值口径不合适（1 B 信号）——
**不是**编译失败，也不是工具坏了。

### 1.1 编译命令（每个变体都一样，只有 `_build/model.tflite` 的内容不同）

```text
bash tools/compile.sh .../ops/_probe/bb04-fc/_build/model.tflite \
                     .../ops/_probe/bb04-fc/_build/model.dla
# 实际展开：ncc-tflite --arch=mdla5.0 --opt=3 --disallow-bridge --num-mdla=2 --l1-size-kb=3072 \
#           --show-exec-plan --show-memory-summary <model.tflite> -d <model.dla>
```

所有变体共用同一条固定编译路径（03 §2.1 的坑：产物里嵌了**绝对路径 + 完整命令行**）。

### 1.2 这个坑本票又量了一次

同一个 fc_a 模型，只在**长一个字符**的实验目录里编译（`bb04-tmp` vs `bb04-fc`），产物从 **7635 B 变成 7637 B**，
精确 +2 B = 路径在产物里出现 2 次（`--model` 与 `--dla-file` 各一次）。所以本报告**只在矩阵内比尺寸**，
不和 02 票的绝对尺寸相减；与 03 票的 `fc_base` 7635 B 可以对上，是因为两票的实验目录名等长。

### 1.3 对 `tools/bbdiff.py` 的扩展（只加矩阵字段，不改既有语义）

FC-E 需要「同形状、只改量化配置」，03 的模型 builder 只会写死 int8 那一档。改动只有两条，**都是数据驱动的可选字段**：

| 新字段 | 取值 | 作用 | 缺省行为 |
|---|---|---|---|
| `model.dtype` | `"int8"`（缺省）| `"fp16"` | 选择常量张量的精度档（fp16 走 `build_ops` 的 F16 助手） | 与 03 完全一致 |
| `model.quant` | `{"input": s, "weights": s, "output": s}`（都可缺省） | 只改**声明**的量化参数；码值仍按 `A_SCALE/W_SCALE` 生成，所以「只改量化配置」的变体**码值逐字节不变** | `A_SCALE/W_SCALE`、output = bias×32 |

**向后兼容证据**：`fc_a`（不写任何新字段）生成的 `model.tflite` sha256 =
`85b1e4016a08737433192955c89cc240d30af1c124193b378bc20a7070f233d2`，
与票 03 的 `fc_base/model.json` 逐字节相同；`.dla` 也是 7635 B、结构与 03 一致。
实现上只是把 `_codes()` 拆成 `_floats()`（浮点源数据）+ `_codes()`（量化）+ 新的 `_declared_quant()`，
flatbuffer 的创建顺序没动。

### 2.1 「两次以上编译一致性」怎么读

**必须**先明确：**同一份模型连编 5 次，5 个 sha256 全都不一样**（上表 sha256 只是 attempt1 的值）。
原因是 03 §2.1 那条：尾部嵌了每次不同的 UUID（+ 少量头部索引字节）。
所以本票「一致性」的口径不是「sha 相同」，而是 **「除已知噪声区外逐字节相同」**：

| 变体 | holdout（第 5 次）vs 第 1 次：不同字节 / 噪声内 / **噪声外** | 结论 |
|---|---|---|
| `fc_b_n128` | 57 / 57 / **0** | 除噪声区外逐字节相同 |
| `fc_c_k128` | 62 / 62 / **0** | 同上 |
| `fc_e_out16` | 108 / 108 / **0** | 同上 |
| `fc_e_out8` | 107 / 106 / **1** | 同上（1 B 是噪声区没覆盖到的抖动，见 §5.3） |
| `fc_e_abs2` | 103 / 103 / **0** | 同上 |
| `fc_e_fp16` | 55 / 55 / **0** | 同上 |

噪声区本身：**251 B / 134 段 = 最大产物的 2.1%**（03 是 214 B/107 段/1.8%，本票变体更多所以并集略大）。
它在 `--repeats 5 --slack 4` 下由每变体**前 4 次**编译两两比对取并集，第 5 次留作 holdout（否则是同义反复）。
逐段清单见 `noise.txt`，主要三簇：偏移 152/200/248/296（步长 48 的单字节）、798…1106（步长 4 的散点）、
尾部 7071..7106（36 B 的 UUID）。

## 4. 区段 + 偏移 + 噪声 + 假设（本票的主表）

### 4.1 先给一张「落址图」（int8 与 fp16 实测，单位 B）

产物可以被切成五段，四个变体的锚点如下（`bias`/`weights` 用生成码值做精确子串/多重集匹配定位）：

| 变体 | 头 0..1646 | 24 B 头 | 常量 A | 24 B 头 | 常量 B | 尾 1588 B |
|---|---|---|---|---|---|---|
| `fc_a` | 1647 | 1647..1670 | bias 1671..1926（256，**逐字节相等**） | 1927..1950 | weights 1951..6046（4096，**多重集相等**） | 6047..7634 |
| `fc_b_n128` | 1647 | 1647..1670 | bias 1671..2182（512，逐字节相等） | 2183..2206 | weights 2207..10398（8192，多重集相等） | 10399..11986 |
| `fc_c_k128` | 1647 | 1647..1670 | **weights 1671..9862（8192）** | 9863..9886 | **bias 9887..10142（256）** | 10143..11730 |
| `fc_e_fp16` | 1647 | 1647..1670 | bias 1671..1926（256，fp16 值**加宽成 fp32**） | 1927..1950 | weights 1951..10142（8192，fp16） | 10143..11730 |

配套的两条结构读数（都在 `manifest.json` 对应的 attempt 上可直接复核）：

- **24 B 头的最后两个 32-bit 字 = 块字节数+8 / 块字节数**（小端）。六处实例全部吻合：
  `fc_a` bias `264/256`、weights `4104/4096`；`fc_b_n128` bias `520/512`、weights `8200/8192`；
  `fc_c_k128` weights `8200/8192`、bias `264/256`；`fc_e_fp16` bias `264/256`、weights `8200/8192`。
  头的第 2 个字含义未知，实测：`fc_a` bias=3 / weights=2，`fc_b_n128` bias=3 / weights=1，
  `fc_c_k128` weights=3 / bias=2，`fc_e_fp16` bias=3 / weights=1（四组不等，不像简单计数）。
- 文件第 1 个 32-bit 字 = **文件大小 − 4**（7631 / 11983 / 11727 / 11727 四个点全部成立）；
  偏移 20/40/44/48/56/60 上是若干「相对文件尾的负偏移」（同一常数跨变体不变），语义未知。

### 4.3 一句话一条假设（每条都可被实验推翻）

| # | 变体 | 观察 | 可检验假设 | 分级 |
|---|---|---|---|---|
| H1 | FC-B | 尺寸 +4352 = 权重 4096 + bias 256；`21..57`（37 B）随 N 变；尾 1588 B 长度不变 | **N 只影响常量块大小与主描述结构里的少量字段**，不改变尾部元数据布局 | 已验证（尺寸拆分 + 尾部等长） |
| H2 | FC-C | 尺寸 +4096 = 只多了权重（bias 不变）；**常量块顺序翻转**（权重 1671 在前、bias 9887 在后） | **K 决定跨核分块策略**，K=128 时权重先于 bias 落址 | 顺序翻转：已验证；机制：**推测**（推翻实验：K=96/N=64 与 K=64/N=256 各编一次，看顺序在哪个点翻） |
| H3 | FC-D | 只换权重：稳定口径下 4080 B，且**恰好**是 1951..6046 这一整段 | **权重常量块 = 产物里一段连续区间，且是唯一随权重内容变化的区间** | 已验证 |
| H4 | FC-D | 该 4096 B 的**多重集**与生成码值完全相同，但逐字节顺序不同（前 64 B 恰好等于行主序，之后开始错位） | 权重在同一区间内被**分块/转置重排**（不是压缩、不是量化变换） | 重排事实：已验证；排列规则：**未知**（推翻实验：用 `n*64+k` 编码的 pattern 权重编一次，直接读出排列） |
| H5 | FC-E1/E1b | 只改 requant 比值：稳定口径下**只有 6343 一个字节**变，0x24(36) → 0x1c(28) → 0x14(20)，比值 1/32→1/16→1/8 | 该字节是 requant 倍率的 **8×log2 编码**（每翻倍 −8） | 三点线性：已验证；语义：**推测**（推翻实验：取 1/64 应得 0x2c(44)；再取 3/64 这种非 2 的幂，看是否整数） |
| H6 | FC-E2 | 声明 scale 全部 ×2（比值不变）：稳定口径 **0 B**，产物与基准逐字节相同（除 UUID） | **编译器只吃 requant 比值**，声明 scale 的绝对值不落进产物 | 已验证（可推翻：改 zero_point 或比值换成非 2 的幂，若产物变则还有别的量化字段） |
| H7 | FC-E3 | int8→fp16：权重 8192 B（fp16，多重集相等）、bias 从 fp16 **加宽成 fp32** 存、尾部仍 1588 B | **精度档只改常量块的编码宽度，不改元数据结构**（尾部结构 1:1） | 已验证（可推翻：用 fp32 FC 编一次，若尾部长度变了则「元数据与精度无关」不成立） |
| H8 | 全部 | 同一模型 5 次编译 sha256 全不同，但**除噪声区外逐字节相同** | 非确定性只来自 UUID + 少量索引字节（03 的结论在本票 9 个变体上复现） | 已验证 |

### 4.4 预注册 vs 结果（把「被推翻」也写下来）

| 预注册 | 结果 | 说明 |
|---|---|---|
| 改 N / K 必有离噪变化（≥1 KiB） | 成立 | 各 10 KiB 量级 |
| 只换权重的变化必须被限制在权重区 | 成立 | 逃出 0 B |
| 改 requant 比值的变化「量级 ≥ 8 B」 | **推翻** | 实测离噪只有 1 B —— 阈值是写矩阵时随手取的，错在假设的量级，不在方向 |
| 改声明 scale 的绝对值会进产物 | **推翻** | 离噪 0 B；编译器只吃比值（H6） |

**关于退出码 1**：`manifest.json` 里 `ok:false`，来自 4 条 check —— 两条是上面被推翻的预注册假设（保留原样，不事后改口），
两条是工具 `noise_share` 口径对 1 B 信号不适用（§5.2）。其余 16 条（含 3 条对照）全部符合预期。

## 5. 已知限度（本票的方法问题，写清楚）

### 5.1 尺寸变化的变体，线性差分被「移位」主导

改 N/K 后文件变长，`diff_offsets` 是**线性**逐字节比较，常量块之后的所有字节都会因为移位而全部记为「不同」
（`fc_b_n128` 的 `1660..7634` 就是这种）。所以对**改形状**的变体，工具的差分只能回答「有没有变」，
**不能**直接回答「哪一段是结构、哪一段是移位」。本报告用「常量块落址 + 大小增量拆分」来代替（§4.1）。
要根治得给 `bbdiff` 加**对齐差分**（按 24 B 头/长度字切块再比），这是下一票的活。

### 5.2 `diff_outside_noise` 对 <100 B 的差分不适用

`fc_e_out16/out8` 的差分里 36~60 B 是 UUID（噪声），真信号只有 1 B，于是 `noise_share` 高达 97%，
按既有判据（`max_noise_share: 0.9`）必然判红 —— **即使信号是真的**。这不是工具错，是判据选错：
小差分应该用「稳定字节」口径（本票 §4.2 的右列）。

### 5.3 holdout 的 1 B 例外

`fc_e_out8` 的 holdout 有 1 B 落在噪声区外。噪声区是 251 B/134 段的**并集**，本身仍有抖动没被覆盖；
`allow_outside_bytes: 8` 的余量就是给这个的（与 03 一致）。

### 5.4 只覆盖单算子 FC

所有结论都限于「单 FULLY_CONNECTED、int8/fp16 常量权重、mdla5.0 / --opt=3 / --num-mdla=2」。
没有覆盖 `.dlb` 打包、`--extract-static-data`（03 已做过）、`--resize`、`gno` 选项。

## 7. 未做 / 留给下一票

- **权重排列解码**：这是本票唯一「看得到但没解开」的东西（结论 3）。材料已经齐了（`fc_a` 的 4096 B 块 + 生成码值都在），
  只差一个 pattern 权重变体。
- **对齐差分**：替换线性逐字节比较（§5.1），否则改形状的变体永远算不清「哪一段是结构」。
- **`stable_diff` 判据**：把 §4.2 的稳定字节口径做成 `bbdiff` 的一个 check kind（数据里写一行即可用），
  伪码：`对每变体的前 N 次编译取「全一致偏移集合」→ 交集内取值不同 = 信号`。
- **上板**：全程离线。任何「产物变了 ⇒ 设备行为也变」都还没有证据。
- 尾 1588 B 里的其余结构（`0x198/0x190`、四个 1、`40 00 00 06`…）没解；`--show-exec-plan` 的文本与这些偏移的对应关系也没对。
