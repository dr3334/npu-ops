# 真维度 decoder 层（T=8, D=896, 14Q/2KV, I=4864）能不能当单算子重放 —— 走到哪了

日期：2026-11-14 · 目标 `ops/decoder_layer_t8_fp16`（61 层，`.dla` 29.9 MB，fp16）

## 0. 结论：还没跑通，卡点换了 —— 现在是「基址+偏移」寻址

玩具块（H=64）能一次提交重放，是因为它的输入/输出地址**作为绝对地址字**出现在命令流里。
真维度这张图不一样：**只有常量区基址是绝对地址字**，输入/输出/temp 都不是。

## 1. 已经拿到的（这一轮新东西）

| 项 | 值 |
|---|---|
| 子命令数 | **2**（`SUBSCMDS n=2`），cmdbuf 尺寸 `32/16/18224` 与 `32/16/17408` |
| 常量区 | **29,847,552 B**（28.5 MB），`iova 0xc4c00000`，**已抓到内容**（新 shim 能力） |
| 输入 | 16384 B @ `0xc4bf4000` |
| 输出 | 16384 B @ `0xc4bf0000` |
| temp | 16384 B @ `0xd3704000` |
| DRAM 账（编译期） | Input 14K / Output 14K / **Temp 14K** / Static 28M |

这三个缓冲的地址**连续**：`0xc4bf0000`（输出）→ `0xc4bf4000`（输入）→ `0xc4c00000`（常量）。

## 2. 卡点：命令流里找不到它们的地址

扫两个子命令的全部 cmdbuf（共 6 个、35 KB）里的 32 位字，与 MAP 表里的 iova>>4 比对：

| 缓冲 | iova | 命令流里的引用次数 |
|---|---|---|
| 常量区 | `0xc4c00000` | **2** |
| 输入 | `0xc4bf4000` | **0** |
| 输出 | `0xc4bf0000` | **0** |
| temp | `0xd3704000` | **0** |

而玩具块是「输入 2 处 + 输出 1 处」都绝对编码。结论：真维度这张图用了**基址 + 偏移**
（DLA 的 tensor base 寄存器 + 每条指令里的小偏移），只有基址（常量区）以绝对地址出现。

这也解释了为什么厂商把三者分配在连续地址上 —— 它们必须落在固定相对偏移上。

## 3. 下一步（两条路）

**A. 复刻连续布局（先试这条，不动 ISA）**

按厂商的相对偏移，自己分配**一整块** `0x4000 + 0xC000 + 0x1c77000` 的缓冲并切分：

```
+0x00000  输出   (0x4000)
+0x04000  输入   (0xC000 里用 0x3800)
+0x10000  常量区 (0x1c77000)
```

然后只 patch 常量基址那 2 个字。相对偏移与厂商一致，基址+偏移寻址就能自动对上。
风险：temp（0xd3704000）离得很远，可能是另一个基址；要单独找它的基址字。

**B. 解码基址/偏移编码**

把 35 KB 命令流里「小数值的字」和已知布局对照，反推偏移字段的位置与宽度。工作量大，但一次做完就通吃。

## 4. 这轮已落地的能力（与卡点无关，可复用）

- **shim 现在会 dump「ALLOC 过但进程没 mmap」的缓冲**（`probe/iolog2.c`）：
  厂商是把 `.dla` 的内容直接写进 dma-buf、不经过 mmap，所以 28 MB 常量区以前根本抓不到；
- 顺带修了 MEM ALLOC 的 size 记录：POST 时请求字段被响应覆盖，必须**在 PRE 时**记下 size（否则 `n=0`）；
- dump 上限从 4 MiB 提到 64 MiB。
