# 08a —— 总时延配对测量：`-P<n>` 到底影响不影响时延

票：`.scratch/compiler-blackbox/issues/08-profile-on-board.md`（08a 切片，只做时延）
基线：`reports/compiler-blackbox-08.md` §5（3 轮、`fc -c 20` / `dec -c 10`）
口径：`reports/timings.md` —— **中位数是主指标、MAD 是离散度、跨轮只认配对交替比值**

## 结论（先看三句）

1. **`-P<n>` 对总时延没有可测影响（已验证，限于本轮噪声水平）**：fc / dec 各 9 轮配对交替，
   逐轮配对比值在 **0.84–1.28** 之间来回跳，没有任何等级在两轮之间稳定领先；配对中位比 0.99–1.03，
   符号检验 p = 0.18–1.00。08 §5 的"看不出趋势"从 *3 轮* 收紧到 *9 轮 × 36 次运行*。
2. **每产物中位数（ms/inf）**：fc = 0.6567 / 0.6673 / 0.6711 / 0.6708（P0..P3，`-c 200`）；
   dec = 2.5970 / 2.5793 / 2.5741 / 2.6402（`-c 50`）。MAD 4.1%–6.9%（fc）、3.6%–5.4%（dec）。
3. **副产品（方法上比 1、2 更重要）：`ms/inf` 不是产物的常数，是"一次跑多久"的函数。**
   同一份 `fc_p0.dla`：`-c 25` → 0.334–0.431 ms/inf，`-c 1600` → 0.774–0.785 ms/inf（**2.3×**），
   约 300 ms 以上的运行进入平台。所以 08 §5 的 **0.3519**（`-c 20`）与本轮的 **0.6567**（`-c 200`）
   **不矛盾，是 `-c` 不同**；跨 `-c` 相除绝对数一律无效（`reports/timings.md` 那条"同一份 .dla 会漂 ±15%"
   在这一点上其实低估了 2 倍以上）。

## 4. 交叉验证：fc 换一个 `-c`（`-c 50`，5 轮）

| 产物 | 中位数 ms/inf | MAD | 比值 vs p0 |
|---|---|---|---|
| `fc_p0` | 0.3664 | 0.0244 | 1.000 |
| `fc_p1` | 0.4140 | 0.0334 | 1.130 |
| `fc_p2` | 0.3926 | 0.0129 | 1.071 |
| `fc_p3` | 0.3931 | 0.0465 | 1.073 |

这里 p1 的中位数比 p0 高 13%，**但这 5 轮的配对比值分别是 1.634 / 0.874 / 1.342 / 1.130 / 0.892** ——
同一个等级在相邻两轮里能差 80%，方向还反过来。**`-c 50` 的噪声明显比 `-c 200` 大，
这一档只能当"结论不随 N 改变"的旁证，不能当主表。** 主表用 `-c 200`，就因为它的逐轮比值收紧到 0.89–1.28。

## 5. `ms/inf` 依赖 `-c`（已验证）：08 的 0.35 与本轮的 0.66 是同一件事

**同产物、同输入，只改 `-c`**（`fc_p0`，两批实验，分别署名）：

**批次 A —— `23-c-sweep.sh`，20 / 50 / 100 / 200 交替 3 轮**

| `-c` | 单轮总时长（约） | 中位数 ms/inf（n=3） | 区间 |
|---|---|---|---|
| 20 | 8–12 ms | **0.4012** | 0.3796–0.5869 |
| 50 | 17–33 ms | 0.4356 | 0.3737–0.6686 |
| 100 | 51–59 ms | 0.5595 | 0.5116–0.5869 |
| 200 | 128–147 ms | 0.6438 | 0.6402–0.7341 |

**批次 B —— 长运行平台，25 / 200 / 400 / 1600 交替 2 轮（每次运行的原值）**

| `-c` | 单轮总时长 | 两次的 ms/inf | `Avg. FPS` |
|---|---|---|---|
| 25 | 8.3 / 10.8 ms | 0.3340 / 0.4312 | 2806 / 2207 |
| 200 | 124.1 / 142.8 ms | 0.6207 / 0.7139 | 1554 / 1267 |
| 400 | 278.9 / 295.1 ms | 0.6974 / 0.7377 | 1373 / 1298 |
| 1600 | 1237.8 / 1255.6 ms | 0.7736 / 0.7848 | 1234 / 1217 |

- 两批合起来：**`ms/inf` 随运行时长单调上升（0.33 → 0.78，2.3×），在 ~300 ms 以上压平**；
  `Avg. FPS` 同步从 **2806 掉到 1217**；
- 跨批次一致性检查：`-c 200` 在两批里分别给出 0.6438（中位，n=3）与 0.6207/0.7139（两次值），同一量级；
- 交叉核对 08：08 §5 的 fc 中位数 **0.3519**（`-c 20`）与批次 B 的 `-c 25` 两次值 0.3340/0.4312 同区间，
  也与批次 A 的 `-c 20` 中位 0.4012 同量级（相差 14%，而同一产物在 `-c 200` 下的轮内漂移本身就有 32%：
  0.5606 → 0.7422）—— **两次测量（08 / 08a）互相一致，差的是 N 不是等级**；
- 因为四个等级**始终共用同一个 N、且在同轮内配对**，这个 `-c` 依赖**不影响**第 2–4 节的结论，
  它影响的是**跨报告引用的绝对数**。

## 6. 对 08 报告的影响

1. §5 的读法可以升级：不是"噪声太大所以看不出"，而是"9 轮 × 36 次、配对设计下仍无 3% 以上的可测差异"。
2. §6 对账里的墙钟 **B = 496.4 µs（p3，`-c 20`）** 与 08a 的 0.65 ms 不同源；对账口径必须**连 `-c` 一起写**，
   或者干脆固定一个 N 重算。本轮没有重算对账（不在 08a 范围）。
3. 以后任何"总时延"数字都应当 **写成 `X ms/inf @ -c N`**，否则不可比。

## 7. 拿不到 / 未知（不编）

- **未知**：`ms/inf` 随运行时长上升的**机制**。候选是持续负载下的 DVFS/降频、或背景负载（load 13）在长时间占用时抢得更多；
  本轮**没有**采时钟或 thermal 证据，所以只能记"现象已验证、机制未知"。若要钉死，下一步是同一批 `-c`
  同时抓 `exec_us`/clock（`40-board-profqos.sh` 那条路）并读 thermal zone。
- **未知**：板子上 load average 13 的来源（谁在吃 CPU）没查；没有"空载对照"这一组。
- **未做**：profile 打开（`MTKNN_ENABLE_PROFILER=1`）时的时延 —— 那是 08 §4 的范围，08a 只测干净态。
- **未做**：两次运行之间的绝对数漂移上限（本次会话内 fc 同一产物在 `-c 200` 下从 0.5606 到 0.7864，
  但这**包含**轮内漂移，不能当成独立的两天对比）。
