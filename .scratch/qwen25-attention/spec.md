# Spec — Qwen2.5-0.5B 的自建 decoder 整块（T=8 / fp16 / 14Q-2KV GQA）

Status: implemented (2026-11-13)
Feature: qwen25-attention
Date: 2026-11-13

## Problem Statement

这个仓库已经把"单算子 → `.dla` → 板端 → 逐位对拍"跑通了 178 个算子目录，`docs/OP-block.md` 也证明了**单头**、head_dim=32 的玩具块（RMSNorm + RoPE + attention + SwiGLU）能在 NPU 上整块下沉、单执行步、板端数值 PASS。

但离"在自己的 NPU 上跑一个**真实形状**的 Qwen2.5-0.5B decoder 层"还差三件事，每一件都缺证据而不是缺想法：

1. **GQA 没有可复现的构造与上板证据**。真实模型是 14 个 query head、2 个 KV head、head_dim=64，而现有块是 1 头 / head_dim=32。更要紧的是：`docs/OP-block.md` 曾把 `--heads 2` 的失败归因为"importer 不认多头"，这条归因**是错的**（见 `docs/OP-gqa.md`，E-112）——根因是块构造器把权重张量按 FC 目标宽度声明，`heads>1` 时声明的缓冲区比实际数组大 14 倍，ncc 在模型加载阶段就退出。**一条假的编译器限制，正在挡住所有多头实验。**

2. **带掩码的 softmax 从未在设备上出现过**（注：本条里「没有 EXP 算子」这个前提已被实测推翻，见文末 Corrections C1）。仓库有原生 `SoftMaxLayer`（β 生效），但加法掩码在 `docs/OP-bmm.md`、`docs/OP-actreduce.md`、`docs/OP-MATRIX.md` 里全部以"未验证"出现。而推理路径里**没有 `EXP` 算子**可用，所以"手写 exp 链"这条路根本不存在，掩码只能靠 `ADD(mask)` + 原生 `SoftMax`。

3. **整块还停在玩具形状**，权重规模、bias、GQA 的 KV 复制都没有进过图。Qwen 的 q/k/v 投影**都带 bias**（`o_proj` 不带），这个事实在 `config.json` 里根本没有对应键，是 transformers 源码硬编码的——漏掉它数值必错。

所以问题不是"怎么写代码"，而是：**在没有真实权重、没有可信编译器结论、没有掩码先例的条件下，怎样一步一步拿到"真实形状的整块在板端 PASS"这个证据。**

## Solution

按依赖顺序推进六件事，全部落在**同一条既有缝**上：一个 `ops/<name>/` 目录 + 一次 `tools/e2e.sh` 运行 = 一份 `compare.txt` 判据。

1. **先把块构造器的张量声明修对**，让 `heads>1` 能进图。这是一切多头实验的地基，且它挡着的不是"我们的新代码"，是"仓库已有的实验"。
2. **造出真实形状的 GQA 单算子**：q 投影 896×896+bias、k/v 各 128×896+bias、o 投影 896×896 无 bias；KV 用 `SPLIT→CONCAT` 显式复制到 14 头（编译器不会替我们广播）；scores 与 PV 优先走 3-D，避免 4-D 被降成 5 层。
3. **造出带掩码的 softmax 单算子**：因果掩码以常量张量加法进入，值取"受控有限负值"（不用 `-inf`，也不用 `-10000`），相加位置在 scale 之后。
4. **把两者拼成整块**：块自包含（两次 RMSNorm、残差、RoPE 常量表、SwiGLU FFN 全在图内），host 只送 `[T,896]` fp16 进、拿 `[T,896]` 出。
5. **把整块串成 24 层**：**每层一个 `.dla`**，逐层 hidden 与 CPU golden 对拍——因为一个 `.dla` 内部不暴露中间张量，逐层定位只能靠"每层一个图"。
6. **最后做一次性真实权重合理性检查**：不追求逐位，只看 logits 分布与 HF fp32 参考的 top-5 交集。

数值判据分三级：单层 hidden（板端 vs CPU）、整网 logits 向量（`atol/rtol`）、整网 top-1（**冻结到真实权重阶段才启用**）。所有权重先用"随机生成后冻结"的那一份，让失败只能指向实现、不能指向权重来源。

## User Stories

1. 作为研究者，我想让所有 `heads>1` 的块实验能进图，这样我不必先怀疑编译器是不是不支持多头。
2. 作为研究者，我想让块构造器在权重数组尺寸与声明形状不一致时**立刻报错**，这样同类 bug 不会再伪装成"编译器限制"。
3. 作为 agent，我想在错误信息里能分清"模型加载期 / 逐层校验期 / 后端期"，这样我不会再把加载期错误当成 importer 限制。
4. 作为研究者，我想让 `docs/OP-block.md` 不再声称"多 head 未通"，这样下一个人不会照一条假限制去设计兜底方案。
5. 作为研究者，我想要一个 head_dim=64、14 个 query head 的 GQA 单算子，这样真实形状的 attention 有可对拍的证据。
6. 作为研究者，我想让 K/V 的 2→14 复制发生在图内且用已证算子（`SPLIT`/`CONCAT`），这样复制逻辑跟随 `.dla` 而不依赖 host。
7. 作为研究者，我想让 q/k/v 的 bias 进图，这样数值不会因为漏掉 72 个 bias 张量而系统性偏移。
8. 作为研究者，我想确认 PV 走 3-D 时是一个原生层、走 4-D 时被降成 5 层，这样我在层数预算上有据可依。
9. 作为研究者，我想要一个因果掩码 + 原生 `SoftMax` 的单算子，这样"掩码能不能在设备上用"这个问题第一次有实测答案。
10. 作为研究者，我想用"受控有限负值"而不是 `-inf` 来做掩码，这样 fp16 下不会出现未定义行为。
11. 作为研究者，我想让掩码在 scale 之后相加，这样掩码的数值量级不会被缩放放大或缩小到失效。
12. 作为研究者，我想看到掩码位置的 softmax 输出确实是 0、非掩码位置与无掩码 softmax 完全一致，这样我能把掩码的错误与 softmax 的错误分开。
13. 作为研究者，我想要一个自包含的整块（RMSNorm + attention + 残差 + RMSNorm + SwiGLU + 残差），这样 host 不参与任何数学。
14. 作为研究者，我想让 RoPE 用预先生成的 sin/cos 常量表，这样不必依赖被 importer 拒绝的 `SIN`/`COS`。
15. 作为 agent，我想让块的输入输出都只是 `[T,896]` fp16，这样每层的边界干净、可以独立替换。
16. 作为研究者，我想让 24 层以"每层一个 `.dla`"的方式串联，这样任何一层错了都能定位到具体层。
17. 作为研究者，我想拿同一份冻结随机权重在 CPU 与板端跑完全相同的 24 层，这样权重的随机性被完全排除在误差源之外。
18. 作为研究者，我想让整网的判据是 logits 向量的 `atol/rtol` 而不是 argmax，这样判据不会被 fp16 末位噪声掀翻。
19. 作为研究者，我想让 top-1 判据只在真实权重阶段启用，这样随机权重下不会出现"语义上没有意义却时绿时红"的假警报。
20. 作为研究者，我想先用一次实测的噪声底来定阈值，这样阈值是"卡住真问题"而不是"卡住随机性"。
21. 作为研究者，我想让 T=8 先打穿、T=128 紧随其后必过，这样第一个里程碑只压一个未证维度。
22. 作为研究者，我不想用 T=8 的 PASS 去宣称真实 prefill 可用，这样对外表述不夸大。
23. 作为 agent，我想让每个工单的交付物只是"一个 op 目录 + 一份 PASS 的 compare.txt"，这样验收标准不依赖人的解释。
24. 作为 agent，我想让回归只比数值、不比 `.dla` 的 sha256，因为同一个 tflite 连编三次哈希都不同。
25. 作为研究者，我想在最后用真实 Qwen2.5-0.5B 权重跑一次，看 logits 与 HF fp32 参考的 top-5 有交集，这样"实现对 Qwen2.5"这句话才有语义锚点。
26. 作为研究者，我想让真实权重那次失败时能立刻分清"是管线错还是权重搬运/格式错"，这样我不会又回到随机权重去重跑 24 层。
27. 作为研究者，我想让整块、整网、真实权重这三档证据分开记录，这样我不会把"结构能编"误读成"数值正确"。
28. 作为 agent，我想让计划与票留在本地 `.scratch/`，这样在公开仓库上不泄露未完成的路线图。

## Implementation Decisions

- **数值精度**：整条路径统一 fp16（权重与激活）。int8 延后到性能阶段；int8 的 requant 边界（±1 LSB）尚未复现，24 层串联后无法与实现错误区分。
- **权重来源**：主路径用**随机生成后冻结**的权重——固定 seed、生成脚本入库、产物不入库、sha256 记入模型元数据。分布用正态且尺度贴近真实权重的实测 std，不用均匀分布（fp16 下 24 层串联会饱和）。真实 Qwen2.5-0.5B 权重只在最后一档做一次性合理性检查。
- **执行路径**：新算子一律"**厂商编译路径先验、自建提交器后置**"。失败时能二分：厂商也错 ⇒ 算子/编译契约错；厂商对而自建错 ⇒ 提交器错。本 spec 的所有证据都在厂商路径上取得；"自建"在本阶段指**自建执行路径与调度**，命令仍借自厂商编译产物。
- **权重驻留**：暂定"逐层常量编译进各层 `.dla`"。这一决定在厂商路径上成立，但迁移到自建提交器时必须重开——常量权重在自建路径上的已知失败模式是"必须落在抓取时的那个 IoVA 上"。
- **测试缝**：整个 spec 只用一条缝——`ops/<name>/` 目录 + 一次 `e2e` 运行。不新增中间张量导出协议。逐层对拍通过"每层一个 `.dla`"实现：每层的图输出就是该层 hidden。
- **GQA 的 KV 复制**：用 `SPLIT` → `CONCATENATE` 在图内显式复制 2 个 KV head 到 14 份，代价约 4 层、仍在同一个执行步。**不采用**"2×7 头"或"14 次单头 unroll"作为兜底——相对单体 1 层是纯亏损（23 层 / 15 层）。
- **BMM 的维数**：scores 与 PV 优先 3-D。PV 在 4-D 下会被编译器降成 `Slice+BMM+Slice+BMM+Concat` 五层，3-D 下保持一个原生层。
- **bias**：q/k/v 三个投影**必须**带 bias（Qwen 的实现里 `bias=True` 硬编码，config 中没有对应键），o 投影不带。这是会静默改变数值的一类事实。
- **块自包含**：RoPE 在块内，但只能消费**预算好的 sin/cos 常量表**（`SIN`/`COS` 被 importer 拒绝），因此 T 必须是静态的。host 与块之间的唯一契约是 `[T,896]` fp16。
- **判据层级**：单层 hidden 用 `atol/rtol`；整网用 logits 向量 `atol/rtol`；top-1 只在真实权重阶段启用。阈值由一次实测的**噪声底**（同一输入在板端连跑两次的差值）决定，取噪声底的 3–5 倍，且严格小于仓库现有 fp16 默认的 `2e-2`。
- **序列长度**：T=8 是第一个里程碑的唯一形状；T=128 紧随其后并列为必过项。在 T=128 通过之前，任何表述都不得声称真实 prefill 可用。
- **不要相信 `.dla` 哈希**：同一个 tflite 连续编译三次哈希都不同，回归只能比数值。
- **记录与追责**：每档证据单独记一条实验记录，结构沿用仓库既有的"假设/预测/做法/结果/适用范围/剩余疑问"。

## Testing Decisions

好的测试只验**外部行为**：一次 `e2e` 运行产出一份 `compare.txt`，判据是"板端输出 vs 独立 CPU golden 的数值关系"。不验内部图层数、不验 `.dla` 哈希、不验命令字节——那些是诊断手段，不是判据。

- **被测单元**：每个 `ops/<name>/` 目录。整块、逐层、GQA、掩码 softmax 各是一个独立目录。
- **golden 独立性**：每个构造器自带独立 numpy 黄金实现，与 flatbuffer 写出代码**零共享**（仓库既有约束 R3：参考与被测独立）。同一个错误理解不能同时污染两侧。
- **既有先例**：int8 档按 `int8_tol` 判 `max_abs`；fp16 档按 `atol + rtol*|expected|`；这两套口径已经在 178 个 op 目录上跑过，直接沿用，只把 fp16 阈值收紧到噪声底之上。
- **掩码的专项判据**：除整体数值外，额外断言"被掩码位置的 softmax 输出为 0"与"非掩码位置与无掩码版本逐位一致"，把掩码错误从 softmax 错误里分离出来。
- **逐层测试**：24 层各自一个目录，每层的输入来自上一层板端输出（不是 CPU 输出），这样误差不会在层间被 CPU 悄悄修正。
- **板端纪律**：所有板端操作持同一把设备锁；每次板端实验前后各跑一次健康检查；任何"自己算对但污染后续"的用例不进入算子库。
- **噪声底测量**：在定阈值之前先做一次"同一输入、同一 `.dla`、连跑两次"的差值测量，把结果写进该算子的实验记录，作为后续阈值的依据。

## Out of Scope

- **增量解码 / KV cache**：本阶段只做 prefill 的单次前向，不保留跨步状态。
- **自建提交器的命令路径**：所有证据走厂商编译产物；命令自生成（真 L4）是后续阶段。
- **int8 整网**：包括 int8 的 requant 边界复现，都不在本阶段。
- **多 batch / 变长序列**：T 固定为静态值。
- **性能与功耗**：本阶段只回答"对不对"，不回答"快不快"。
- **最终 token 生成 / 采样 / tokenizer**：只到 logits。
- **公开到 GitHub**：代码、计划、票都只留本地。

## Further Notes

- 编译侧的关键证据在 `docs/OP-gqa.md`（占号 E-112）：14 头单算子、完整 14Q/2KV attention、完整 decoder 层都能 `EXIT=0`、单执行步；头数扫到 1024 仍是一个原生层。**没有头数上限**，硬限制只有 rank ≤ 4 和 int8 每行 < 16 B 会 bridge。
- 错误措辞可以区分阶段，这是排障的第一判据：`the given model` = 加载/解析期，`the input model` = 逐层校验期，`Cannot find an execution plan` / `Bridging is disallowed` = 后端期。之前两轮把一个加载期错误误判成 importer 限制，就是因为没看这句话。
- 环境坑：本机存在**两份 SDK**（一份在仓库同级的 `mtk/` 下，一份在 `deepseek_ workspace` 的兄弟目录），编译脚本的默认解析与探针实际使用的是不同的那份；两边都能编出结果，但排障时不要混用路径。
- 决策依据见 `docs/adr/0001`（全 fp16）、`0002`（自建=执行路径）、`0003`（随机固定权重 + top-1 冻结）、`0004`（本地 tracker）。
- 词汇以根目录 `CONTEXT.md` 为准：`整块`、`prefill`、`增量解码`、`GQA`、`KV head`、`head_dim`、`随机固定权重`、`命令捕获`/`命令自生成`、`自建提交器`。
## Corrections（证据订正，2026-11-13 实现阶段实测）

**C1 —「推理路径里没有 EXP 算子」不成立。** 配对正对照实测：EXP 编成原生 ExpLayer，1 个执行步、EXIT=0；不可用的是 LOG(fp16) 与 COS。
方案（加法掩码 + 原生 SoftMax）不变，但**理由要改**：钉死这条路的是 fp16 的 exp 值域（大于 11.09 上溢），手写 MUL+EXP 链在夹具实测量级下 640/896 溢出成 inf。详见 docs/OP-masked-softmax.md §3.2。
教训：**没有正对照的「不支持」结论不算结论**（与 E-112 同类错误）。

**C2 —「D=896 的 RMSNorm 不能用 MEAN」不成立。** 原归因是 tools/build_rms896.py 的索引错位 bug（act() 之后又 const()，索引指向 int32 的 axis 张量），修好后 MEAN 变体 6 层/单执行步/板端 PASS（ops/rms896_d896_T8_vA）。详见 docs/OP-rmsnorm.md 的订正一节。

**C3 — FC 的 N 维度上限 65535。** 单体 FC(8x896x151936) 在编译期被拒（MDLA: Dimension should be <= 65535）；分块 FC + CONCAT 可行（票 08 已上板 PASS）。CONCAT/RESHAPE 到 151936 不受此限。

**C4 — 编译通过 + 单执行步 ≠ 数学正确。** 三个独立对照（h2 的 reshape、GQA 的 wrong_reshape、PV 的 badlayout）都是 EXIT=0/单步但板端错到 rel_l2 0.14–1.23。本 spec 的每条「编译侧已通」结论都必须配一次板端对拍。
**C5 — 阈值的 2e-2 上限在大输出量级下不可达（判据口径订正）。** 本 spec 原文要求「阈值严格小于仓库现有 fp16 默认的 2e-2」，但那条默认值隐含前提是 |out| ≈ 1。量测结果：1 层整块 |out| 最大 0.4836（fp16 层边界下限 2.258e-3），14 头 H=896 整块 |out| 达 8.46（下限 2.148e-2 —— **已经超过 2e-2 本身**），两层链的 h2 |out| 1.27（下限 6.353e-3）。
采用的判据（全批次一致，写进每个 model.json）：
`atol = rtol = max(4·2⁻¹¹·max|out|, 4·floor)`，其中 `floor` 是**独立于设备**的 fp16 下限（把 numpy golden 逐层按 fp16 舍入模拟一遍得出），阈值在**板端跑之前**登记并留 `tolerance_revision` + 依据；报告里同时给 `max_abs/max|out|`、`rel_l2` 与噪声底。
因此出现两个绝对值 > 2e-2 的登记（h14 3e-2；两层链 h2 2.54135e-2），两者的相对口径分别为 2.4e-3 / 2.0e-3，且实测偏差（2.197e-2 / 6.348e-3）**都贴着各自的下限**（多 0–2 ULP），不是实现误差。gqa_scores 的 10.48 属同一现象（|out| 5368，实测偏差 0）。

**C6 — 「24 层串联」改成 2 层 + 硬件结论（实现范围订正）。** spec 的 Solution 5 与 US 16/17 要求把整块串成 24 层、每层一个 `.dla`。实际做的是 2 层（票 10），理由有两层：
（a）票面理由：2 层已能暴露所有跨层问题（残差累积、层间契约、每层权重重新装载），再加到 24 层是 12 倍的机械重复，不提供新信息；
（b）**实测硬件结论（2026-11-13 复核，订正此前一处指标误用）**：1 层整块 61 层 / 单执行步；静态权重每层 28.5 MiB，24 层 ≈ 684 MiB（+ logits 图 260 MiB ≈ 944 MiB）。**容量不是拦路虎**——设备实测 `MemAvailable ≈ 6.1 GB`（MemTotal 11.3 GB / MemFree 0.49 GB / Cached 5.0 GB）；此前写的「空闲 RAM ~273 MB」取的是 `free -m` 的 free 列（= MemFree），用错了指标。真正的限制是**装载形态**：每层一个 `.dla`，而厂商 `neuronrt` 一次只吃一个 `.dla`、每层一个进程 ⇒ 每层 145 ms 载入+启动，24 层 ≈ **3.5 s/token**（SDK 的 RuntimeAPI 支持一进程多 model、clone 共享常量区，但本仓库从未实测）；另有一次性 host→device 搬运 ≈ 24×1.0 s + 7.8 s ≈ **31 s**。前向本身 1.6–2.25 ms/层，且 T=8 已是**权重带宽主导**（29.8 MB / 1.6 ms ≈ 18.5 GB/s）。

**C7 — T=128 已通过（本 spec 的必过项 1 层整块档）。** `ops/decoder_layer_t128_fp16`：x[128,896] fp16 → out[128,896] fp16，EXIT=0、**61 层（与 T=8 逐项相同，T 只改维度不改拓扑）/ 1 个执行步 / 无 bridge**；板端 PASS：max_abs 1.7334e-02 = 35.50 ULP @max|out|=0.627，rel_l2 1.311e-02，噪声底 0（0/114688 code 差）。
阈值 6.7871e-2（= max(4·2⁻¹¹·max|out|, 4·floor)，跑前登记），比 2e-2 宽的原因已在 C5 覆盖：**设备误差只比设备无关的 fp16 下限高 0.75 ULP**（floor 34.75 ULP），而该下限的 99% 来自 softmax 概率——夹具的 bias 把分数抬到 ±5165，fp16 粒度 4.0、缩放后 0.5，11.6% 的 (head,row) 近并列，softmax 因此有约 12% 抖动（反事实判别力仍有 5.4–7.0×，T=8 是 39–50×）。
边界（不许夸大）：**T=128 的 1 层整块 PASS ≠ 真实 prefill 可用**——24 层、logits、KV cache 都还没在 T=128 上做过；T=8 的产物在这次改动后逐字节未变（tflite sha 6d2e10c7…）。

**C8 — 「真实权重一次性合理性检查」这一档没有实现（范围订正，非遗漏）。** spec 的 Solution 6 / US 25 要求在最后用真实 Qwen2.5-0.5B 权重跑一次、看 logits 分布与 HF fp32 参考的 top-5 交集。实际状态：
（a）票面就把这一档排除在外（票 10 明写「本票不含真实权重」），10 张票的验收里没有任何一项依赖真实权重；
（b）本机确实有真实权重（`D:\ai\Qwen2.5-0.5B-Instruct`，bf16 safetensors），票 02 用它**测出了逐张量的真实 std/mean** 来定夹具尺度（这是本 spec 唯一真正用到真实权重的地方）；
（c）真正端到端跑真实权重需要的不是这条管线，而是 C6 的权重换入：24 层 × 28.5 MiB 常量权重放不进这台设备的空闲内存，且 HF fp32 参考侧（transformers/torch + 网络）在本环境未验证可用。
所以这一档被**明确记为未实现的下一个里程碑**，而不是「做过并通过」。`top-1` 判据继续保持冻结（ADR 0003），全批次都没有启用。

**C9 — logits 之前缺 Qwen 的 `model.norm`（已知差值，不是实现错）。** 夹具 25 个张量只覆盖 embed + layer0/1，Qwen2.5 在最后一层之后还有一个 final RMSNorm（`model.norm`）才进 LM head。因此 `ops/two_layer_logits_t8_fp16` 是对 h2 直接做输出投影。接真权重时必须补这一层（一个 6 层 RMSNorm），这是与 HF 参考对比时的已知差值，已在 docs/OP-two-layer.md 记录。
